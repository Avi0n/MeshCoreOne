## Investigation and acceptance boundary

The pinned decoder intentionally stops at a short header, unknown type or short
value, returning the accepted prefix. The existing native decoder preserves that
prefix, record boundary and order, with an explicit `Incomplete` result.
`TelemetryResponse.dataPoints` exposes the same prefix; `decodeResult` exposes
the incomplete state. Strict rejection is opt-in. The pinned encoder traps on
invalid conversions/preconditions; native typed errors and atomic records are a
deliberate adaptation. GPS Int32-to-low-24-bit wrapping is deliberately rejected.
See the [deviation](../../deviations/WP-105.md); passing tests do not approve
these product adaptations. No production change was needed.

`LPPR118ContractTest` adds 23 independently expected complete-result cases,
69 malformed-tail cases (short header, unknown type followed by valid-looking
data, short temperature value), and nine original encoder entry-point rejection/
recovery cases. Each complete case asserts the entire ordered channel/type/value
list, completion state and consumed length. Every tail asserts the unchanged
prefix, exact unconsumed bytes, diagnostic metadata and both strict error paths.
The same payload is passed to the actual `TelemetryResponse` consumer, retaining
raw bytes and its cached incomplete result. No same-implementation round trip
produces an expected value or packet.

The nine encoder cases check exact typed range metadata, byte/count atomicity,
an unchanged prior snapshot, successful subsequent append and reset. Existing
`LPPEdgeCaseTest` additionally covers all scalar bounds, nonfinite values, every
motion/GPS axis, raw widths, value-kind errors and all integer/timestamp bounds.
Its existing unsigned-current/signed-decoder asymmetry remains unchanged.
