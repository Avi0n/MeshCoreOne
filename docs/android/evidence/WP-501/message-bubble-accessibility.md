## Actual consumer and bounded native adaptation

The App uses the existing current-radio `ComposerEnvironment` contacts/device,
real `AppChatContent.rendering` preference snapshots, current theme/contrast,
font scale, locale and observed map-network state. Nickname uniqueness follows
the frozen configuration; key-prefix resolution and path formatting reuse actual
native producers. There is no fabricated fallback contact, DTO, footer or item.
An intentionally unbound standalone graph keeps its historical basic text/status
label rather than synthesizing `EnvInputs.DEFAULT` or fake preferences.

`MessageFragmentBuilder.makeItem` constructs an **accessibility-only
envelope/footer projection** from the real message and inputs. Its unused
content-fragment/preview fields are not the canonical rich-media snapshot, are
not rendered, do not trigger preview fetches and do not replace the incumbent
body/media services or coordinator. The returned real footer supplies policy
flags, path, region and status/counters; actual localization supplies descriptions.
The original raw text is always retained; translation remains removed.

The optional label slot is threaded through both public timeline entry points
and the real App screen; existing rich body, media, links, retry and Details
remain intact. Lazy-list keys, paging, anchors and effects are unchanged.
The whole bubble is deliberately **not** cleared, which would erase actionable
link/media/retry descendants. Tests require one configured combined description
without a clearing/live-region flag and separately invoke preserved actions.
This is **not** proof of once-only TalkBack speech or native traversal. Real
TalkBack/device verification remains unperformed, as do API37, screenshots,
hardware and whole-WP acceptance.
