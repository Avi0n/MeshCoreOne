## Historical DATA-20 active-search cancellation repair

The pinned `KeyGenerationServiceTests::Cancellation is respected()` permits a
search that finishes before immediate cancellation. The former native mapping
only cancelled a LAZY job before startup, proving zero entropy calls but not an
executing loop. The original-case mapping now targets a deterministic dispatcher
and the existing RFC8032 seed, whose public key cannot match `AA`. Reaching the
second seed proves one unsuccessful attempt completed; cancelling the actual
search job there must propagate cancellation, complete cleanup, return no
identity and prevent a third seed request. The seed-call assertion bounds a
broken loop independently of the coroutine test timeout.

The zero-seed pre-start test remains separate, as does entropy-thrown
cancellation in `KeyGenerationBoundaryTest`. No production code, cryptographic
algorithm, key format or persistence schema changes. This is additional native
test evidence, not a changed product contract or a new parity waiver.
Execution is currently **unverified**: the retained WP-503 native-execution lock
blocks local Gradle. Explicit WSL toolchain readiness passed independently. See the
[bounded repair record](../evidence/WP-204/active-key-search-cancellation.md).

Automatic backup uses credential-protected `noBackupFilesDir` independently of
the unchanged app's `allowBackup=false` and all-domain cloud/device-transfer
extraction exclusions. Actual APK/config inspection is still required; a module
manifest alone is not proof. Passwords remain outside manual app backups.
Explicit identity export is sensitive. WP-203 must handle channel/radio secrets,
parent/child restore, public-key remapping and committed preference completion;
this module does not add a whole-envelope codec or Room plaintext duplicate.

The frozen source Compression `.zlib` oracle is **raw DEFLATE**, not RFC1950
framing. Unix fractions, canonical UUID/enum/Codable bytes,50MiB compressed/
512MiB expanded bounds and both-direction real Swift restore remain WP-203.
No macOS codec, API37 device, TEE/StrongBox, credential-upgrade, signing, release
or optional translation legal/privacy approval is claimed here.

The DataStore1.2.1 runtime is not Apache-only or native-free. Its relocated
protobuf4.28.2 binary declares BSD-3-Clause. The exact1434-byte embedded terms
are preserved at the specifically coordinator-admitted app asset path, plus
the exact1732-byte v28.2 Google copyright/license in owned module assets because
the embedded text omits a copyright header. Input hashes/versions and static
RuntimeVersion constants are recorded independently; no artifact code is run.
DataStore core includes four`libdatastore_shared_counter.so` ABIs whose actual
static PT_LOAD alignments are16384. Final APK inspection must prove their
presence/zip/ELF alignment separately from device-native-load evidence, which
has not occurred. Other linked source/license and release obligations remain.

Windows `core.autocrlf` changed the exact admitted app BSD notice from1434 to
1458 raw bytes after rebase. The native build's owned notice verifier first
checks that canonical-LF bytes still match the independent publisher hash,
then normalizes **only that admitted app asset** before app asset merging.
Unknown/different text is a typed build failure, never rewritten into a
matching substitute. Four module license assets use scoped byte-preserving
Git attributes. No global config or unrelated source/license is changed.

The API-aware policy follows the first-party
[`setUnlockedDeviceRequired`](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder#setUnlockedDeviceRequired(boolean))
contract: Android12-14 require a secure lock for generation, delete affected
keys on secure-lock removal and have additional biometric/shared-profile
bugs; the documented avoidance is enabling the option only on Android15+.
The native adaptation is explicit, not a caught-error permissive fallback.
SDK31/32/33/37 Keyguard/UserManager/spec regressions and deliberately reversed
close-waiter scheduling exercise the reviewed defects; declarations are not
counted as passes until the real runner emits complete nonzero XML.
