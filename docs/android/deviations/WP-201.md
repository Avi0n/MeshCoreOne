## Immutable native values and representation

Swift value DTOs become immutable Kotlin values with explicit copy operations.
All binary fields reuse MIT protocol `Bytes`; model collections use defensive,
content-equal `SnapshotList`, `SnapshotSet`, and `SnapshotMap`. Nested values are
also immutable. Swift Double equality (equal signed zeros, unequal NaNs) is
preserved explicitly instead of relying on JVM data-class Double equality.
Dates are immutable `Instant`. Room stores seconds and nanoseconds separately,
including negative epochs, with both components in date indexes and ordering.
It does not narrow to milliseconds or allocate from an untrusted date/count.

UInt8/16/32 remain unsigned domain types and checked nonnegative SQLite Int64
columns. Source Swift Int counts, offsets, sequences, dimensions, RSSI values
and run durations use Long. Contact/discovered stored out-path lengths remain
Int64: the source's historical `-1` flood value projects by truncation to `255`,
without copying SwiftData storage or migration numbering.

UUID values are stored as canonical uppercase text, not Java name UUIDs.
DeviceIdentity retains the first sixteen SHA256 bytes **without** setting
version/variant bits. String stableUUID retains the two wrapping djb2 streams
and little-endian stream bytes. Factories receive an explicitly resolved
radioId; they do not derive a replacement for an existing/restored partition.
The Device surrogate is distinct from radioId.

Application formatted-hex parsing stays in the GPL model module and preserves
filtering, optional failure and odd-length rejection. It is not the protocol
hex parser. V-contact derivation keeps its exact salt, length and fail-open
non-V semantics. Technical POSIX formatting and locale-sensitive display
collation remain distinct; region labels use native localized/numeric
collation without normalizing persisted names or crypto input.

## Schema, identity and lifetime boundaries

Android starts at Room schema **1**, with all seventeen actual persistent
source model types, generated by admitted Room2.8.5/KSP2.3.12. Only linked
message repeats and linked trace runs have foreign-key cascades; nullable
relationship links retain source orphan semantics. Contact, channel, Device,
reaction, pending-send and room-session references are values, not invented
automatic cascades. Their full atomic deletion/adoption algorithms belong to
WP-202. Upsert is Room Upsert, never destructive SQLite REPLACE or database
fallback. No historical Android upgrade is invented.

Radio-owned child rows use `(radioId, id)` keys and radio-prefixed indexes.
The neutral contract adds `EntityKey(radioId, id)` to source id-only child
operations, and explicit radio context to DTOs whose source wire form omits it
(repeats, room messages, trace runs). It prevents equal IDs from crossing
partitions without adding fields to the frozen backup DTO wire contract.
Device registry IDs remain globally unique so pre-identity pairing lookup is
unambiguous. Bluetooth addresses/CDM handles and legacy Apple peripheral UUIDs
are connection handles, never persistent radio identity.

**Explicit source-scope exceptions, not blanket exemptions:** debug logs and
URL preview cache are process-global. Node history is shared by full remote
node public key, as the source DTO/schema/query has no companion-radio field.
Inventing one would change history and make legacy backup attribution
ambiguous. The actual SQL deletion guard refuses to delete node history while
*any* radio session references its key. A real two-radio assertion proves this.
These source behaviors are retained visibly rather than silently repartitioned.

Room entities stay behind database/data boundaries. All thirteen source
persistence roles, their current store extensions, pending/failure/metadata
roles, polling handlers, typed errors and neutral factory seams are declared,
without no-op production repositories. Process database/preferences survive
connections. Epoch/generation tokens and per-session factory inputs are
neutral contracts; WP-207 owns implementation and WP-303 actual graph assembly.
The factory is generic over WP-107's real session type, not a future fake.

Native row-to-DTO projections surface malformed widths, unsupported enums,
malformed UTF8/JSON/base64/UUIDs as `DatabaseValueException` with field/cause.
The explicitly supported `-1` notification migration sentinel retains its
legacy-muted/all projection without dirtying a read. Contact raw types, raw
channel flood-mode/region fields, room raw status and RX payload nibble remain
preserved where the source supports unknowns. Unlike source corrupt-row
fallbacks/empty trace-data catches, genuine corruption does not become an
empty/successful row; WP-202 must map/notify the typed cause.

## Verification adaptations and evidence limits

Robolectric4.17 simulates API31 and executes real SQLite/Room constraints,
transactions, Flow reads, checked projections and persistent reopen. Windows
file-backed WAL sidecars fail in both Robolectric native and legacy VFS.
The file-reopen/no-destructive-fallback assertion therefore explicitly uses
native SQLite **TRUNCATE journal mode in the test only**. Production keeps
Room AUTOMATIC mode. No test is skipped; no production journal fallback or
physical WAL/device certification is claimed.

Room's generated JSON omits default-false notNull and empty foreignKeys/indices;
the exact schema assertion recognizes only those generator defaults and
compares every real table column, index and identity hash. Schema content was
not hand-authored to make assertions pass.

Gradle-generated module-local locks are owned configuration, using existing
pins/verification metadata. Regeneration rewrote unchanged shared locks' line
endings; only byte-proven newline-only files were restored to their original
Windows checkout form. No shared catalog, pin, XML, workflow, gate, source
catalog or progress file is changed. GPLv3 app/MIT MeshCore notices remain.
Ordinary hosted checks do not replace protected approval, formal parity review,
hardware, license, release-signature or whole-port acceptance.
