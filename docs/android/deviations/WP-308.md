## Native adaptations

- **D-1 Verification.** Compose UI-test, Robolectric and coroutines-test are not on the locked feature
  classpath. State, parsing and tokenization are tested on the JVM with an injected scope and a manual timer.
  The Compose layer compiles and passes lint; it is not rendered. Six source ids that host UIKit/Liquid Glass
  views in a window (`TiledViewInputBarChromeTests` x4, `ChatInputBarThemedChromeTests` x2) are bound as
  `platform-adaptation` **source scans** (`ComposerUiSourceScanTest`): the timeline is the weighted child above
  the bar in a `navigationBarsPadding().imePadding()` column, and the bar color derives from the theme surface.
  They are structural checks, not layout or rendering measurements.
  A lock amendment for real UI tests would need: `androidx.compose.ui:ui-test-junit4` and `ui-test-manifest`
  (in the version catalog, not locked for `feature:chats`), `org.robolectric:robolectric` plus
  `androidx.test.ext:junit`, and `org.jetbrains.kotlinx:kotlinx-coroutines-test` (virtual time instead of the
  manual `ComposerTimer`).
- **D-2 Swift semantics.** UTF-8 length counts a lone surrogate as 3 bytes (a Swift `String` repairs it to
  U+FFFD); graphemes use the JDK `\X`; trimming is `.whitespacesAndNewlines` (trims U+200B and NBSP, keeps
  U+FEFF). Expected values were produced with `swiftc` 6.3.2 (`evidence/WP-308/oracle/`): byte/grapheme counts,
  trimming, `Character.isWhitespace`, mention percent-encoding and decoding, coordinate regex edge cases,
  hashtag regex, `NSDataDetector` behavior, and the strippable-scalar classes. JDK 21's `\X` lacks the Unicode
  15.1 Indic conjunct rule (inherited from WP-213).
- **D-3 URL detection.** The JVM has no `NSDataDetector`. `LinkDetection` links `http(s)://` and `www.` hosts
  (the latter resolve to `http://`) and trims trailing sentence punctuation and unbalanced `)`. Bare domains
  (`example.com`) and email addresses are **not** linked, whereas Swift links them (oracle `url` rows). The same
  scoped choice was made by WP-218 `LinkUrlExtraction`. A mention such as `@[Node WCMesh.com]` still carries the
  mention link; the pre-pass span outranks any URL over the same characters.
- **D-4 Token colors.** iOS freezes a `Color` on each token at detection time. Android tokens carry a
  `LinkColor` role (`BASE`, `MENTION_IDENTITY` + name key, `HASHTAG`, `OUTGOING_TEXT`) and a self-mention flag;
  `MessageBody` resolves them from the active `ThemeFrame` (`identityColor`, `hashtag`, `outgoingText`).
- **D-5 Emoji.** Entry point, picker UI, search (`localizedStandardContains` over label/shortcodes/tags),
  frequent-first ordering, 20-item MRU and the 6-item recents rule are ported. The dataset is behind
  `EmojiCatalogSource`: bundling Emojibase JSON or adopting AndroidX `emoji2`/`emoji2-emojipicker` is a
  dependency decision for a lock amendment. No such dependency was added.
- **D-6 IME.** `commitPendingInput` has no Android equivalent: the field is a `TextFieldValue`, so composing
  text is already part of the value and the holder's draft. Composing characters therefore count toward the
  byte limit as they are typed. Hardware Enter sends, Shift+Enter inserts a newline (iOS `onSend` path).
- **D-7 Send.** `send()` captures the trimmed draft, clears the field, disables the button for 1 s and while in
  flight, calls `createPending*` then `sendPending*`. A failure before the pending row exists restores the
  draft (unless the user typed again) and shows a failed state; a failure after it leaves the failed row to the
  WP-307 retry path. Cancellation is rethrown and never reported. The chat send queue and ACK tracking stay
  with WP-208.
- **D-8 Deferred UI pieces.** `AnimatedGIFView` (needs `AnimatedImageDrawable` through `AndroidView`; the
  inline image shows a static frame from the image source), the viewer's share action (needs a FileProvider
  share intent), the shimmer `PreviewSkeleton` (a spinner/solid placeholder is used), `ChatComposeBarFade`
  (surface elevation instead of a fade), and `ShareContactPickerSheet` (contacts feature; `onPickContact` is
  the seam and its result returns through `insertShared`).
- **D-9 Timeline slot.** `ChatTimeline`/`ChatTimelineRoute` gained one optional parameter,
  `messageBody: @Composable (MessageDTO, Boolean) -> Unit`, defaulting to the previous plain `Text`.
  `ChatConversationScreen` supplies the linkified `MessageBody` and an `attachments` slot for preview/inline
  image cards. Per-message preview and inline-image holders are created by the app (they need the WP-213
  fragment pipeline), so the screen renders them only when `attachments` is supplied.
- **D-10 Regex.** `\w`, `\d`, `\s` are spelled out (`\p{L}\p{Nl}\p{M}\p{Nd}\p{Pc}` plus joiners, `\p{Nd}`, the
  ICU `White_Space` set); `\p{Alphabetic}` is not portable to Android's regex. The word class differs from ICU
  only for non-letter Other_Alphabetic symbols (e.g. circled letters).
- **D-11 Link opening.** Body and card taps route mention links locally, other chat URLs through the shared
  `ChatLinkRouter`, and open externally only `http(s)` URLs (`LinkOpenPolicy`). `javascript:`, `intent:`,
  `file:` and custom schemes are never handed to the system; the composer UI contains no `WebView`.
- **D-12 Mention overlay.** The suggestion list is a 200 dp, 20-row overlay anchored to the bottom of the
  timeline box (directly above the bar); it does not need the iOS `chatKeyboardLiftPadding` because the whole
  column is inset by the IME.

## Issue #208: contextual rich-span contrast repair

This bounded follow-up uses base `d958471ab4835813881a5e7af36e8249a8b273a4`, after the actually merged

**D-13 Painted-surface context.** Frozen `UnifiedMessageBubble` paints outgoing `theme.accentColor`
(failed messages use the source failed fill), while native `ChatTimeline.MessageBubble` paints
`MaterialTheme.colorScheme.primaryContainer`; incoming bubbles use `surfaceVariant`. Source palette
pair assertions therefore cannot establish contrast for the native consumer. `MessageBody` now resolves
the existing BASE, MENTION_IDENTITY, HASHTAG and OUTGOING_TEXT roles against that actual surface using
the existing design-system helpers. The trailing optional `backgroundColor` is source-compatible for
direct/channel callers. Other consumers, including the independently owned WP-310 room bubbles, must
pass their actual opaque composited surface together with their contextual `baseColor`.

Incoming mentions retain the frozen name/FNV/hue/saturation/brightness algorithm, with the actual bubble
luminance supplied as its background context. Global palette, avatar/category algorithms and all 38
effective theme/scheme/contrast frames (including forced-dark Ember) are unchanged. Outgoing hashtags
retain the source OUTGOING_TEXT override; they are not reassigned to the incoming hashtag or arbitrary
caller base role. Ordinary text retains the 4.5:1 requirement; incoming identity mentions retain 7:1
in high contrast. Requiring 7:1 for every source accent/failed-red fill is not the existing outgoing
text requirement and can be unreachable.

**D-14 Self-mention composition.** The source uses a mention-colored translucent highlight (0.15
incoming, 0.30 outgoing). Native rendering freezes that fill from the bubble-contextual color, composites
its emitted (including sRGB/alpha quantization) color over the actual bubble, then corrects the foreground
against the composite. If a high-contrast highlight makes 7:1 unreachable for any foreground, its seed
is minimally toned toward neutral while retaining the identity hue and source opacity. This is a
contextual highlight adaptation, not a palette/avatar change. This deliberately allows
foreground and fill seed to differ rather than introducing a circular foreground/fill dependency or
weakening the identity threshold. Normalization, original message text, token ranges, URLs, underline,
bold, custom accessibility actions, preview behavior and send/draft/session lifetimes are unchanged.

`MessageBodyContrastTest` checks emitted base/link styles, all 38 effective frames, seven identity-name

## Issue #212: disabled hardware Return fallback

## Issue #215: composer facade and service-owned send queue

**D-16 Queue-shaped consumer contract.** Frozen `ChatViewModel+Messages`, `+Channels` and `+SendQueues`
create the actual pending message, then enqueue a typed `DirectMessageEnvelope` or
`ChannelMessageEnvelope` through the service-owned queue. The composer facade previously copied unused
low-level wire send/resend receipts and `preserveTimestamp` flags from `MessagingSendPort`; those cannot
be faithfully implemented over the durable queue. `ComposerSendPort` now retains its two pending-create
methods and exposes Unit-returning `enqueueDM`, `enqueueChannel` and `signalDMEnqueued` using the existing
model envelopes. Signal-only retry requires the caller's real persisted retry row and never inserts it
again. No receipt, attempt count or timestamp-preservation shim is manufactured.

The holder enqueues the pending row's actual ID and, for channels, its original text/timestamp and the
target slot. The local node name is read after pending creation as in the frozen channel caller. Enqueue
acceptance finishes the composer operation, not wire transmission or delivery; the queue owns durable
attempts, draining and timestamp policy, and the actual message/timeline owns delivery state.
Existing immediate draft clearing, cooldown, creation-failure restoration, newer-draft preservation,
saved-pending failure and cancellation propagation remain intact. Typed queue disconnection maps to
the existing disconnected failure state; persistence failures are reported without fake success.
After a non-cancellation enqueue failure with a saved pending row, the holder invokes
`recordLocalEnqueueFailure(messageId)` as the frozen event-stream helper does. The App adapter owns the
unless-delivered persistence guard and real status/event publication; a creation failure, successful
enqueue or cancellation never invokes that operation. The original typed enqueue error remains
reported and visible; no synthetic timeline status replaces the actual durable row.

Owned state-holder/fake regressions cover exact direct/channel envelope identity and metadata, current
node capture after delayed creation, accepted-but-still-pending status, typed queue failure, delayed
creation failure and cancellation for both targets. The existing WP-502 producer retains the real
AppChatsFeature pending/retry/resend/event adapter and queue integration assertions; this shared API
correction is serialized to the same WP-308 producer, reservation and PR. The App adapter is not
independently recreated: the authoritative App-only WP-502 commit
`0ae51f7e1ca9c8a4c7aa962a0dfadae59923bf8e` is transferred byte-identically into this branch after trusted
`app-build-launcher` admission and same-attempt scope evolution to revision 4. Its producer attribution
is retained. The initial traceability-only correction retained the original `AndroidOnly: WP-407`
native App-binding disposition and removed conflicting `PortedFrom` declarations; the frozen queue and
event-stream behavior references remain documented here. The authoritative App-only successor
`78f33d27a9cf777d5bc319175f2c3c498f34e85e` now uses exclusively `PortedFrom` declarations, retaining the
WP-407 native assembly context as an ordinary comment without weakening the validator. Its executable
implementation is adopted unchanged from the same sole WP-502 producer.
The consumer binds actual durable enqueue/signal operations, single-persistence DM retry, captured
queue generation before App suspension, channel retry/resend metadata and unless-delivered local
failure persistence/event publication with current-thread failure-seen behavior. The consumer retains
source-faithful event ordering: the durable failure event and conversation refresh
precede fallible seen bookkeeping. Only typed persistence failure is logged there; cancellation still
propagates. A seen-write failure cannot suppress the already-published message failure. WP-502 retains the
queue integration assertions and broader flow fixtures. Core queue `notify=false`, service lifecycle
and independent fixtures are unchanged. Consumer integration and exact-candidate native/hosted outcomes
