# WP-315 line-of-sight workflow: adaptations and deviations

Reference: `db14559b39d32322b06477c6ae676112f583db50`. Acceptance IDs:
`WP-315-behavior`, `WP-315-boundaries`, and `WP-315-source-test-parity`.
This completion builds on the previously merged and source-accounted logic layer
and makes that behavior reachable through the native Android app.

## Delivered workflow

Package `com.meshcoreone.android.feature.tools.los` now includes:

- lifecycle-owned `LineOfSightStateHolder` state and cancellation;
- contact/repeater selection, map long-press point selection, tap relocation,
  dropped pins, copy/open-coordinate actions, editable endpoint/repeater heights,
  relay placement and retry/error states;
- source RF frequency and refraction controls, with reanalysis from cached
  in-memory profile samples;
- real WP-218 Open-Meteo elevation fetching and WP-212 RF analysis through
  feature-owned ports and app-owned adapters;
- direct and relay results with distance, path loss, diffraction loss,
  clearance status and textual values in addition to color;
- terrain, line-of-sight, first-Fresnel-zone, obstruction, endpoint and relay
  chart rendering with a TalkBack summary;
- stable MapLibre marker/line identities, source-equivalent 1.5x camera fitting,
  preserved operator camera state and non-consuming pointer-to-coordinate
  conversion using the current reported Web Mercator viewport.

The app adapter maps WP-218 and WP-212 values field by field. It does not
reimplement RF analysis, and cancellation is rethrown rather than translated
to a failure. Elevation failures retain their typed identity through the
adapter and use the existing localized app-layer description.

## Native Android adaptations

1. **Layout.** The Swift bottom-sheet/expanded-window presentation is an
   adaptive Compose layout: compact windows stack map and scrollable controls;
   widths of at least 840 dp place them side by side. Actions remain 48 dp,
   action rows do not compete with point text at 200% font, and chart meaning
   is available as text and semantics.
2. **Map integration.** WP-312 exposes a north-up, untilted MapLibre surface but
   not raw map-coordinate callbacks. A non-consuming Compose gesture observer
   converts the surface's reported camera bounds through Web Mercator. It
   leaves MapLibre pan/zoom and repeater marker selection intact. Incoming
   elevation/results rebuild overlays without replacing the current camera;
   fitting occurs only for initial repeaters or an explicitly completed
   analysis.
3. **Process wiring.** `AppContainer` owns one bounded HTTP producer and the
   LoS dependency adapters for its process lifetime. Composition receives
   dependencies; it never constructs networking, persistence or radio
   services. The current process contact store, radio identity and connected
   device frequency are read when the feature state is configured.
4. **Tools composition.** The merged WP-316 diagnostics root remains the
   default Tools content. Only the existing `LINE_OF_SIGHT` destination is
   intercepted for this workflow, leaving the shared Tools home/list to its
   active WP-314 owner.
5. **Units and text.** RF input remains MHz and the connected radio frequency
   is converted from kHz exactly once. Elevation/height/distance display follows
   the device measurement system while RF loss remains dB. Source status names
   use the existing localized resources.
6. **External maps.** Android geo intents replace MapKit's open-in-maps action.
   The action is disabled when no installed application resolves the intent.

## Intentional limits

- Elevation and the standard OpenFreeMap style are network-backed. A missing
  network, missing elevation samples, rate limit or HTTP failure produces the
  existing visible loading/error/retry or elevation-warning state; mesh
  messaging and navigation remain available. WP-218 and the frozen source do
  not define a persistent elevation cache, so this WP does not invent one.
- The source's precise live-GPS recenter button is not added. Android currently
  declares only coarse location for onboarding and WP-312 explicitly excludes
  a precise-location map permission. Point selection, repeater selection and
  relocation remain complete through map picking; no new permission or
  success-shaped approximate fix is introduced.
- Native Android does not reproduce the source's map-style, label and
  clustering toolbar controls. The approved WP-312 standard style, readable
  labels and clustering are fixed on for this operator view.
- No device, radio, measured-reception, hardware or offline-cache claim is made.
  Results are labeled elevation/terrain/Fresnel analysis and attributed to
  Open-Meteo; they are modeled path clearance, not measured packet reception.

## Directly necessary support edits

The manifest owns the feature package, tests and these records. Ordinary app
composition, feature build wiring, the strict feature dependency lock and
traceability validation are directly necessary support edits. `portmap.py`
admits app-owned Kotlin support through the existing trusted
`app-build-launcher` path plus `add-direct-support-wiring` operation. Paths
outside that policy rule continue to fail closed.
