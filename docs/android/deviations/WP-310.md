# WP-310 deviations

## Native sheets and share handling

The Swift screens use `NavigationStack`, `ShareLink`, `UIPasteboard`, Core Image QR generation and a
camera scanner. Android exposes Material 3 bottom-sheet content with injected share, copy, QR rendering
and scan callbacks. This keeps platform side effects outside composition and avoids adding a camera
permission or scanner dependency in WP-310; the separately owned QR/platform adapter can bind the scan
callback without changing validation, slot selection or join behavior.

## Translation

Message translation is removed from active scope, not deferred or required for future builds.
Room labels and rendering preserve original message text and app localization. No provider, model
or translated message chrome is introduced.

## Integration boundary

The initial feature contribution exposed rooms/channels dependency seams; subsequent App integration
made `AppChatsContent` -> `RoomConversationRoute` reachable. Issue #207 binds room links through that
consumer using the existing dispatcher/router, radio-scoped contacts and native external URI handler.
It does not create a second sender, radio owner, preview loader or rich-text renderer.

## Issue #207: bounded room accessibility adaptation

The frozen bubble combines its body/status children and replaces their spoken label. Android uses a
per-message `clearAndSetSemantics` boundary containing the original incoming author/body or outgoing
body/room status exactly once. Timestamp remains outside that boundary; visual grouping and sender
visibility are unchanged. Visible status distinguishes all six stored statuses. Spoken status uses
the frozen room mapping (including sent/delivered's existing "Message delivered" resource), not
inferred direct-message ACK behavior.

Named Retry (failed only, real message ID) and link actions are attached to that same node. Shared
formatter/action helpers preserve document order, URL deduplication, the eight-link cap and localized
names; the existing `MessageBody` still handles visual formatting and pointer taps. An unconsumed
link action returns false rather than claiming success. No changing-timeline live region is added.

The shared rich-text renderer is contained in a native Material bubble: incoming uses the resolved
incoming surface; outgoing uses the theme accent, except failed messages use the approved failed
bubble composited on the actual room canvas. Body foreground is explicitly resolved for that surface
with the shared accessibility helper and unchanged contrast floor. Author/status remain outside the
bubble. This restores the frozen surface/foreground pairing rather than drawing outgoing white
hashtag spans on a light canvas. The consumer passes its actual opaque painted bubble and source
preferred foreground to the WP-308 producer's shared `MessageBody` context API. Ordinary/outgoing
body and hashtag text retain the existing AA floor; identity-mention increased-contrast handling
remains shared-renderer-owned. This consumer does not override all token colors, modify the shared
renderer, or duplicate its contextual span/highlight correction.

Remember Password uses one labelled, 48dp-minimum `Role.Switch` row with the real checked value and
toggle callback; the displayed Switch has no independent toggle handler. The route forwards the
resulting choice to the existing join service.

Native Compose regressions run in App's already-declared Robolectric task and dependencies under
the admitted `app-build-launcher` support capability. No App build, WP-501 binding, WP-503 audit or
other WP acceptance is modified. Device/TalkBack and formal full-WP acceptance remain unverified.

## Production follow-up: reload scheduling and mounted room actions

The pending debounce slot now has the frozen Swift lifetime: it is cleared before the awaited
fetch, not after it. A successor can therefore be scheduled while an older fetch is suspended.
The existing generation guard also invalidates snapshots as soon as an event or successful local
post/retry arrives, so an old fetch cannot erase an optimistic row or overwrite a newer status.
Completion/cancellation of an older job only clears its own slot. Fetch/read side effects stay
serialized through the existing mutex; this does not introduce a second data or send pipeline.

Room actions remain a room-specific sheet, as in Swift; room DTOs are not converted into ordinary
chat DTOs with incorrect reaction/delete/path capabilities. The consumer reuses WP-309's existing
`MessageAction` IDs and the shared mention formatter and sender-contact matcher, without editing
the WP-309 actions implementation. Original room availability is captured at presentation.
Translation remains removed. Native tap/long-press and a localized Details accessibility action
open the same sheet. Reply/Mention dismisses the sheet before requesting composer focus.

Send DM uses the current radio-scoped contact snapshot already loaded by the mounted App consumer.
It excludes blocked contacts, preserves case-insensitive mesh-name matching, presents every match
with its public-key identity, and calls the real chat-navigation callback after selection. A lookup
failure remains visible through the existing room error surface; it is not replaced with a new
network/contact-resolution pipeline. The app binds the existing reactive Reply With Quote preference.

Send Again calls the existing room post service with the original text, never Retry or the unrelated
draft. As in the source, an outgoing message retains Send Again while disconnected/read-only; the
real service reports any connection/permission failure to the room error surface. A successful normal
send clears only the submitted draft, preserving text entered while the service was suspended.
An in-flight send cannot be submitted twice through Send/Send Again.

The successor's advisory claim could not replace the historical WP-310 attempt. Per trusted
`reserve.py`'s advisory-intent contract and the coordinator's correction, this is recorded honestly,
not treated as a source-edit veto for the explicitly assigned, capability-admitted isolated worktree.
No historical identity/authorization/ledger row or hard execution lock is rewritten. Controller
reconciliation and unavailable local execution remain separate prerequisites, not fabricated evidence.
