# WP-309: reactions, actions, and message details

Reference: `db14559b39d32322b06477c6ae676112f583db50`. Integrated base:
`f34f68d0416da113c2cd0d274c44937f6c41a5d3` (`origin/main`). Owner:
`chats-ui-engineer`.

## Native adaptations

- **D-1 Compose action surface.** Swift menus and sheets are represented by a retained state holder and an
  adaptive Compose content surface. Compact layouts show one scrollable detail pane; widths of 600 dp or
  more place the selected path map beside the details. Action execution stays callback-driven so the
  existing timeline/composer owners retain reply, copy, resend, reaction, and delete behavior.
  The successor removes the active Translate button under the approved translation scope removal;
  the inert enum remains for consumer compatibility, not as a reachable action or deferred feature.
- **D-2 Shared-map rendering.** Path details consume WP-312's `MapLibreMapSurface`, OpenFreeMap catalog,
  marker/line algebra, camera calculation, and visible provider attribution. WP-309 adds no provider,
  account, key, Google service, location permission, offline claim, or alternate map behavior.
- **D-3 Durable-data boundary.** `MessageActionsDataSource` is the feature-owned adapter for process
  contacts/discovered nodes, repeat/reaction records, and block/mute writes. The state holder never owns a
  radio session. Feature-local name confidence, reaction-summary, and SNR presentation types avoid a
  forbidden concrete `feature:chats` to `core:services` edge. Cancellation propagates; read, block, and
  mute failures remain typed UI state rather than becoming empty success.
- **D-4 Path resolution.** Stable endpoint/hop IDs are derived from identity bytes, not list positions.
  Ambiguous short hashes remain fallback matches and cannot be drawn as exact located hops. Duplicate
  located hops are rendered once while preserving the original arrival order and completeness result.
- **D-5 Delivery accessibility.** Delivery state is exposed as a textual enum and Compose labels include
  status, SNR quality/value, repeats, path availability, and selectable reaction counts. Color remains
  supplementary. Deterministic JVM tests cover these contracts; physical TalkBack, screenshots, and device
  rendering are not claimed.
- **D-6 Preview adaptation.** Shared-map camera/canvas state replaces Swift snapshot image storage inside
  this feature. Width bucketing and stable preview keys are preserved, while snapshot download/cache
  ownership stays with WP-312. No network-backed preview success is manufactured.

## Deliberate boundaries

The manifest owns the `actions/` implementation and test packages. Existing WP-307 timeline and WP-310
room/channel files are preserved unchanged; they consume the public action/state callbacks when assembled
by their screen owner. No feature-to-feature dependency, second persistence store, radio lifecycle, new
permission, or replacement MapLibre/OpenFreeMap path was introduced.

- **D-9 Test host.** Mounted public-route regressions live in the existing App test harness through an

## Selected-arrival endpoint restoration successor

Base: `f539e0ac5454d9099ec2d1b0e8d0f93e9a7c0e54`; source remains
`db14559b39d32322b06477c6ae676112f583db50`. Prior action/reaction successor PR #276 is merged;
this is a separate bounded repair, not a whole-WP acceptance claim.

- **D-10 Endpoint rows are not map geometry.** Frozen `MessagePathContent` renders sender, intermediate
  hops and receiver for every available selected arrival, including zero-hop; only `isPathUnavailable`
  suppresses rows. Android now does the same while preserving its existing Flood summary and First/#2
  selection adaptation. Sender uses the existing `senderResolution` and first-byte `senderNodeId`:
  outgoing uses local name, incoming channels keep their on-air sender name, incoming DMs retain exact,
  fallback and unresolved name confidence. Receiver uses the matching radio name or localized You.
  A same-radio device without coordinates still has an identity. `messagePathLocation` forwards that
  name separately; `PathEndpoint`, map geometry/availability and authorized location selection are unchanged.
  A different radio supplies neither identity nor geometry. No coordinates are invented.
- **D-11 Native endpoint presentation.** Material columns wrap identity, localized role/node-ID and the
  selected arrival's localized signal quality/SNR to avoid horizontal clipping at 200% font. Sender and
  receiver each form a merged semantic text group; the possible-match button remains a separate 48dp
  action with localized explanation/dismissal. The existing signal-quality classifier is reused.
  The localized source accessibility signal sentence doubles as visible feedback, instead of SF Symbols
  or color-only bars. Missing SNR omits signal info, as in the source; it never falls back to the canonical
  message's SNR when another echo is selected. Existing intermediate/repeat rows and block/reaction behavior
  are not changed.
- **D-12 Focused consumer evidence boundary.** Four added mounted App-harness methods drive the real
  `messagePathLocation` adapter into the public `MessageActionsRoute`/holder/data-source path, including
  deferred durable reads, nil/empty zero-hop, a real echo DTO, outgoing echoes, unknown/different-radio,
  true unavailable, CJK/200% and recomposition/read-count assertions. They do not mount the complete
  AppContainer/radio graph or claim native/device, TalkBack, map, screenshot/golden or whole-WP parity.
  The existing WP-502/501 test paths (including separate nil-path/hop-count candidates) are untouched.
  See `docs/android/evidence/WP-309/path-endpoints.md` for actual commands and pending verification.

- **D-13 Selected-arrival path copy.** Frozen `MessagePathContent` shows the arrow-separated path and
  Copy control after the receiver only for nonempty hops. The same consumer now writes the selected
  arrival's comma-separated uppercase hex through Compose's platform clipboard adapter, used by the
  real App route as well as mounted tests. It does not dispatch `MessageAction.Copy`, copy message text,
  dismiss details, or read services again. Existing localized visible/accessibility/hint resources and
  a 48dp Material text button replace the icon-only Apple control; a wrapping monospaced column keeps
  the path/action reachable at 200% font. Native button feedback replaces the Apple-specific success
  haptic; no unverified success notification is introduced. Zero-hop and unavailable paths omit the
  copy/display block. Two additional mounted methods inspect Android's actual clipboard, selection,
  recomposition, English/Chinese semantics, retained details and suppression. Execution remains subject
  to exact-candidate verification; no native/device/TalkBack claim.

- **D-14 Road-distance banner and incomplete disclosure.** Frozen preview/banner displays abbreviated
  locale-aware road units, no duplicate hop count, and an incomplete explanation even when no distance
  can be computed. The native path consumer now calls a single owned banner for both placed and
  unplaceable paths. Nullable distance remains absent, never zero. Platform Android ICU formats the
  meter input with public `usage("road")` on API 33+, using the current Compose resource locale.
  API 31–32 has no public road-usage API (the public skeleton API only starts at 37). Its bounded
  fallback uses ICU's regional measurement system and localized abbreviated unit/precision formatting:
  metric transitions at 1,000m to km; US/UK transition at one mile, otherwise feet/yards, with up to two
  significant digits. This deliberately does not clone WP-313's Foundation-derived 900m/half-mile
  transitions, fine/coarse increment ladders or symbol tables. Short-distance rounding and thresholds
  therefore differ on 31–32. Android ICU/CLDR versions can also differ from frozen Foundation in
  spacing/unit spelling; exact Apple-output/device parity is not claimed. The original 12,400m
  component scenario runs on API 31 and 33, metric/US
  units, French decimal, 200% layout, null-distance transitions and real route unplaceable flow have
  authored mounted assertions. A 48dp localized Material text control opens a scrollable explanation
  dialog with native dismissal/Done instead of the shared source's icon/popover. Map geometry,
  availability/provider/rendering and cache/capsule behavior are unchanged; deterministic tests do not
  instantiate a renderer, access the network or fake map success. Existing map entry gains its original
  localized view-on-map accessibility purpose.
