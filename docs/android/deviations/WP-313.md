# WP-313 deviations

The user-directed takeover retains the merged #70 logic and completes the native
screens and production consumers. WP-210/211/212/311/312 and the native shell
are merged prerequisites, not outstanding ownership or service blockers.
The frozen Swift pin remains `db14559b39d32322b06477c6ae676112f583db50`.
See [`evidence/WP-313/README.md`](../evidence/WP-313/README.md) for scope and evidence.

## Architecture

- Feature modules may not depend on core:services or on other features
  (`ModuleGraph.kt`). Service calls go through feature-owned ports in
  `dependencies/RemoteNodesPorts.kt` (`RepeaterAdminPort`, `RoomAdminPort`,
  `BinaryTelemetryPort`, `NodeSnapshotPort`, `ContactOcvPort`,
  `RemoteNodeHistoryStore`, `RemoteNodeLoginPort`,
  `RemoteNodeFaultClassifier`), bundled by `RemoteNodesFeatureDependencies`.
  `AppRemoteNodesFeature` adapts the actual process store and per-connection
  WP-209/210/211 services to them. Swift's
  `@MainActor () -> Service?` providers stay providers, read at call time.
- Swift pattern matches on `RemoteNodeError.timeout`,
  `sessionError(deviceError(remoteNodeNoResponseYet))` and
  `BinaryProtocolError.sessionError(.timeout)` become
  `RemoteNodeFaultClassifier` calls. The neutral fault seam
  is implemented in the app over the actual typed service and firmware errors;
  features do not import `core:services`.
- View models are plain state holders (`MutableStateFlow` of an immutable
  data class, `suspend` actions, injected `RemoteNodesClock` and
  `CoroutineScope`), not androidx `ViewModel`.
- User-facing text is `RemoteNodesText` (resource id + args, verbatim text, or
  a `Failure(throwable)` the screen renders with WP-304's
  `userFacingMessage`). Logic never resolves Android resources.
- The app supplies the existing tools CLI through a composable callback.
  There is no remote-nodes-to-tools dependency. Both terminals reuse the app's
  typed error projection, including the source reboot-timeout behavior.
- Captured remote ports reject stale connection generations and mismatched
  radio keys. History reads remain available from the process store offline.
- Contact Detail hands remote actions to the app through WP-311's neutral
  callback contract. The app maps them to feature-owned launch inputs, preserving
  authentication, login-free chat-node telemetry and the actual room-session
  conversation handoff. Saved-state tokens omit these private contact identities.
- The newly resolved remote-nodes map graph is locked with existing pinned
  artifacts. The full local scaffold test also exposed a mainline duplicate
  tracing POM checksum entry; only the identical duplicate is removed, retaining
  the same checksum and fail-closed publication-coverage tests.
  Complete debug/release configuration locks are generated through actual
  dependency-report, release-compile and resolver tasks.

## Native UI and maps

- SwiftUI forms/disclosures become scrollable Material 3 sections with current
  compact/list-detail widths, labelled toggles, native Back/IME/keyboard actions,
  masking, 48dp actions and accessible error/countdown announcements.
  Admin writes, CLI commands, reboot and region operations require confirmation;
  permission revocation or disconnect prevents a pending write.
- Charts use the existing series, scrub geometry, units and precision models.
  Canvas drawing is supplemented by an adjustable Slider and textual sample/date
  readouts; it does not require chart gestures to access values.
- Location history has an inline decimated preview, a separate full-window map
  without pin decimation, report-to-pin camera focus and a center-all control.
  The settings picker selects the shared map camera center and never requests
  GPS permission. Its initial region is captured once per opening; camera reports
  move the selected coordinate/crosshair without resetting either camera span.
  Missing fixes are not plotted as real node locations.
- Map rendering and attribution use shared `core:maps`, MapLibre Native 13.6.1
  and the approved OpenFreeMap base provider. Satellite and topography remain
  explicitly unavailable under the approved provider; no new provider terms,
  tile downloads, permissions or offline rights are assumed.
- The unchanged shared engine's base-region offline behavior and static 16KiB
  compatibility are inherited from WP-312 (#140). Native tests inject local map
  fixtures; they do not establish real tiles, radios or physical-device execution.
- The standalone no-dependency entry retains the existing explicit unavailable
  scaffold contract. Production MainActivity supplies the real dependencies.
- The focused Contact Info source cases now have actual native input, Backspace,
  focus/color/height, edited Apply, 200% font and resize equivalents. UIKit itself
  is not executed by the Android tests.
- Resolver calls use their source-defined no-user-location branch: the current
  platform producer exposes permission and one-shot location acquisition, not
  a cached user-location port. Remote maps and path names never require GPS.

## Behavior differences

- Cancellation always propagates. Swift's catch-all blocks also caught
  `CancellationError` and kept going (or showed its text); here in-flight
  flags (`isApplying`, loading, countdown) are reset and the cancellation is
  rethrown. `flashSuccess` clears the success flag before rethrowing.
- The success flash, retry delays and countdowns sleep on the injected clock.
- Admin services may call the CLI handler off the main thread. Swift hopped to
  the main actor first; the late-reply bookkeeping is guarded by a lock
  instead.
- Displayed failures are reported through the standard UI error presenter.
  Failed saved-password deletion logs a nonfatal warning and preserves successful
  authentication, as Swift does. Region/default-scope read failures are explicit.
- A failed history refresh retains previously loaded snapshots and exposes the
  failure instead of replacing valid cached history with a success-shaped empty
  state. Cancellation clears loading and propagates.
- History stores are remembered for the screen lifetime rather than rebuilt
  during catalog recomposition. Only explicit Refresh or a new identity/service
  lifetime reloads the snapshot; the history clock is injected for deterministic
  date windows and native fixtures.
- Formatted native text follows current resource configuration. The CLI keeps
  its screen-owned input/history while its remembered diagnostics adapter
  forwards subsequent messages to the current resource locale.
- Native numeric drafts can temporarily contain incomplete or non-finite input;
  validation rejects it before transport rather than silently replacing it with
  the last valid value.
- `MeasurementSystem` is injected instead of reading `Locale.current`;
  production reads it from ICU (`LocaleData.getMeasurementSystem`).
- `NodeSettingsPresentation.convertUTCToLocal` builds the two-digit date from
  the locale's short date pattern; Apple's `dateTime.year(.twoDigits)...`
  skeleton can order fields differently in some locales.
- `LPPDataPoint.formattedValue` renders timestamps with the platform
  medium-date/short-time style, not Apple's `.abbreviated`/`.shortened`.
- Distances use a haversine on the mean Earth radius (`common/GeoDistance`)
  instead of CoreLocation's ellipsoid; they only rank resolver candidates and
  label SNR badges.
- `LocalizedStandardOrder` reproduces `localizedStandardCompare` for the cases
  in the oracle (numeric runs, diacritic/case tiers, significant spaces); it is
  built on `java.text.Collator`, not ICU numeric collation.

## Foundation reproductions verified with swiftc

Oracle sources are committed under `evidence/WP-313/oracles/*.swift.txt`:
number formatting (`.number`, `.fractionLength`: half-even on the shortest
decimal, signed negative zero, six-digit default cap), Foundation unit
coefficients (°F, inHg, ft), `localizedStandardCompare`, Swift `Double`
interpolation for CLI arguments (`1e-05`, `45.0`), and the region parsers'
`Character` semantics (CRLF is one character; a lone CR is not a separator;
the default-scope reply splits on `"\n"` only).

## Remote CLI tab retention (TS-25)

Original: `NodeCLIViewModelTests` (banner names the node; history cap 100; output cap 1000;
idempotent configure) exercise a view model whose terminal state outlives tab switches.
Android: the holder and its four cases live in `feature/tools` (`NodeCliStateHolder`,
`NodeCliStateHolderTest`) and are created by the app slot `AppRemoteNodeCli`
(`remember(session.id)`). `RemoteNodeManagementRoute` previously composed the CLI slot only
while the CLI tab was selected, so every tab change disposed the holder and lost the terminal.
Now `RetainedTabContent` composes the slot on first selection and keeps it composed (zero size,
clipped, removed from semantics, and with focus/keyboard cleared) while another tab is shown; it is
disposed only when the route leaves composition or the session identity changes. The slot contract,
`canWrite` gating and the app's cancel-on-dispose /
cancel-when-disabled effects are unchanged. A hidden CLI keeps a running command until it is disabled,
the session identity changes, or the route is disposed; it is not cancelled on tab change.
Not changed: the app slot and `feature/tools` are outside WP-313 write paths.
