# WP-305 onboarding: deviations and type-placement decisions

Source specification: `db14559b39d32322b06477c6ae676112f583db50`. Scope: `android/feature/onboarding/`
only. This is the onboarding feature module, not app-graph wiring (WP-303) and not device-verified.

## Native adaptations

- SwiftUI `NavigationStack` path becomes `OnboardingState.onboardingPath` (StateFlow, immutable list
  copies); the welcome root is the empty path. System back pops the path through a dependency seam.
- Sheets (`.sheet`) become Material3 `ModalBottomSheet`; alerts become `AlertDialog`; Liquid Glass
  containers/buttons become Material3 `Card`/`Button`. Hit targets are 48dp (iOS 44pt).
- `UserDefaults` becomes `OnboardingFlagStore` (same `hasCompletedOnboarding` key).
- Permissions: notifications and location cards are marked **optional** (iOS shows them unmarked);
  "Continue" is never gated. Bluetooth is requested just in time on the first "Add device" tap,
  not on the permissions screen; local-network (API 37) when the WiFi sheet opens. A denied
  permission turns the card/notice into an "Open Settings" action.
- `AccessorySetupKit` pairing is the app's CompanionDeviceManager flow behind `OnboardingPairingPort`.
  `DeviceScannerSheet` (macOS-only in the original) becomes the in-app scan fallback sheet, shown only
  when `OnboardingScanFallbackPort.isRequested`.
- iOS `triggerLocalNetworkPrivacyAlert()` (UDP socket trick) is not ported; Android uses the
  `ACCESS_LOCAL_NETWORK` runtime permission where it exists.
- Simulator-only primary CTA (`targetEnvironment(simulator)`) has no Android analogue; demo mode is
  `OnboardingDemoPort` (3 taps on the pair title unlock it, preserved).
- `MeshAnimationView`/`PulsingAntenna` use Compose Canvas / infinite transition; "Reduce Motion" is
  approximated by animator duration scale 0. Geometry/timing constants are carried exactly.
- Preset frequency uses `Locale.ROOT` `%.3f` (matches `.number.precision(.fractionLength(3)).locale(.posix)`).
- The region/country search is a case-insensitive substring match, not `localizedStandardContains`.
- `DeviceMenuTipCoordinator` is the feature-owned slice of `AppState.donateDeviceMenuTipIfOnValidTab`
  (valid tabs Chats/Nodes/Map). The TipKit donation itself is a callback the app binds.
- Retry alert after a retryable preset failure: 3 attempts, then the generic fallback message
  (`RetryAlertState.maxRetries == 3` carried over).

## Issue #250: exhausted preset retry message

The preset retry dialog preserves the original error below three attempts and renders the existing
localized `alertRetryEnsureConnected` remedy at exhaustion, matching
`MC1/Views/Settings/Sections/RetryAlertModifier.swift` at the pinned source revision above.
This primary WP-305 repair retains PR #72 provenance; threshold, titles, buttons, dismissal,
fallback, reset, cancellation and service behavior are unchanged. The mounted regression remains
owned by WP-502 in PR #249; no device or radio acceptance is claimed.

## Type-placement decisions (feature modules may not depend on core:services/data/runtime/connectivity)

| Local type | Mirrors | Reason |
|---|---|---|
| `OnboardingPresetOption(id,name,frequencyMHz)` | `RadioPreset` (core:services) | picker shows only these; adapter applies `isSelectable` filter + name sort |
| `OnboardingRegionCatalog`, `OnboardingCountry/Subdivision`, `AdministrativeAreaKind` | `RegionalAreas` (core:services) | country/subdivision lists and display names |
| `OnboardingPermissionSnapshot`, `PermissionStatus`, `OnboardingPermissionKind` | `PermissionSnapshot`/`ConnectivityPermission` (core:connectivity) | per-card status; adapter maps platform grant/denied-after-request |
| `OnboardingConnectOutcome` (+ `OnboardingConnectionSnapshot`) | `DevicePairingError`/`PairingError`, `DeviceConnectionState` | cancel/ignored are benign; failure carries a ready `UiText` and an optional other-app retry id |
| `OnboardingScanFallbackPort`, `OnboardingScanDiscovery` | `BluetoothScanPairingService`, `RSSIScanTracker` output | uses `core:ui` `RSSITuning.SignalTier` |
| `OnboardingPresetOutcome` | `SettingsService.applyRadioPresetVerified` + `SettingsServiceError.isRetryable` | |
| `OnboardingFlagStore` | `UserDefaults`/DataStore | |
| `RegionSelection` | used directly from core:model | allowed edge |

`OnboardingFeatureDependencies` (OnboardingDependencies.kt) is the single interface the app layer binds.

## App-layer wiring still required (WP-303)

`FeatureRegistry.kt`/`NativeNavigationShell.kt` still call `OnboardingEntry(route, navigate)` (third
parameter defaults to null, which keeps the honest "not yet ported" shell). The app must pass an
`OnboardingFeatureDependencies` backed by: PairingCoordinator/CompanionPairingService (+ scan fallback),
the connectivity permission state, ConnectionManager/WiFi connect, `RegionResolver`/`RegionalAreas`/
`RadioPresets`/`SettingsService`, demo mode, and the DataStore flag. It must implement
`rememberPermissionRequester` with `rememberLauncherForActivityResult(RequestPermission)` and
`InterceptBack` with `BackHandler` (activity-compose 1.8.2 is locked only for runtime, not on this
module's compile classpath, so the seams live in the app). On completion the entry navigates to the
chats root; the app should also treat `hasCompletedOnboarding` as the source for first-run gating.

## Resource gaps (core:l10n is frozen; not edited here)

- Troubleshooting strings (`troubleshootingSystemSettings*`, factory-reset copy) are iOS wording
  (Settings > Bluetooth/Accessories); reused unchanged. `deviceScanError*Mac` and
  `permissionsLocationAlert*` are unused. No string exists for a "granted" announcement on a permission
  card, so the granted checkmark is decorative (the missing Request button is the signal).

## Test-dependency amendment needed for Compose UI tests

The feature lock has only JUnit4 + kotlin-test; no Robolectric, `androidx.test:core`,
`compose.ui:ui-test-junit4`/`ui-test-manifest`, or `kotlinx-coroutines-test`. A future lock amendment
needs those (the `mesh.android.robolectric` convention plugin plus `libs.androidx.compose.ui.test.junit4`,
as core:ui uses) to add composable assertions (TalkBack labels, 48dp targets, wide-width layout,
semantics of each sheet). Until then only coordinator/state/animation-model logic is tested and the
screens compile and lint clean.

## Unverifiable without a device

CompanionDeviceManager chooser, BLE scan/bond/adapter-off transitions, runtime permission dialogs and
Settings round-trips, real location/geocoder region detection, WiFi/TCP connect, edge-to-edge insets and
IME behavior, tablet/foldable layouts, TalkBack traversal order, animation frame pacing.
