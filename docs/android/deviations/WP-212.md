# WP-212 native diagnostics, logging and RF adaptations

Reference: `db14559b39d32322b06477c6ae676112f583db50`.
Owner: `services-porter`. **External contribution:** this was prepared outside the
dispatch controller, with no lease, session or receipt. The adaptations below are
proposed for coordinator review, not approved gates. All production code is pure
JVM under `core/services/.../services/diagnostics/`, and the RF types are in
`diagnostics/rf/`. No build, lock, manifest or shared paths are written.

## A-01: process-wide log hub and buffer ownership

`DebugLogBuffer.shared` and its bounded pending queue stay a process-wide,
lock-guarded hub. Assigning a buffer takes the pending entries and hands them to
the new buffer **synchronously and in record order**. Swift's drain `Task` could
in principle be overtaken by later records.

The Swift buffer's unowned `Task`s become work in an injected `CoroutineScope`.
Time is an injected `DebugLogClock`. These values are unchanged:
- 5 s timer
- `maxBufferSize` 50
- `maxPendingEntries` 500
- the requeue/backpressure rule (`count + requeue < 2 × max`)
- the reentrancy-guarded drop summary
- connect-seeded `lastPrune`
- `DebugLogRetention` prune cadence

A save interrupted by **cancellation** puts its batch back at the front of the
buffer and rethrows. Swift cancellation cannot interrupt a save. Re-saving is
idempotent because the Room store upserts by id.

## A-02: platform log sink

There is no `os.Logger` on the JVM. `core:services` cannot reference Android's
`Log`, so `PersistentLogger` writes every level to an injectable
`DebugLogPlatformSink`. Its default is `java.util.logging`, which Android
forwards to logcat. INFO and above also go to the hub, as in the source, and
DEBUG is log-only. `error.localizedDescription` becomes the exception message,
or the class name when there is none.

## A-03: CommandAuditLogger and LogRedaction

The source actor holds no state, so `CommandAuditLogger` is a plain thread-safe
class with ordinary (non-suspend) methods. Every format string is byte-identical.

`LogRedaction` keeps Swift's grapheme semantics: `String.count`/`prefix` use
`BreakIterator` character instances, and `split(maxSplits:)` omits empty
subsequences.

**Source behaviour kept for parity but flagged for review:**
- `cliCommand("Password hunter2 extra words")` logs `"Password hunter2 [REDACTED]"`. The split keeps the first two tokens, so the secret leaks.
- A leading space (`" password x"`) is not redacted.
- CLI *responses* are never redacted.

The tests pin these exactly. Fixing them is a deliberate divergence the
maintainer should choose; it isn't done silently here.

## A-04: RF path analysis

The `RFCalculator` constants, formulas, rounding and result types are unchanged,
and `CLLocationCoordinate2D` maps to the existing `model.Coordinate`. Result
types keep Swift equality: `0.0 == -0.0`, NaN never equals itself, and
`ObstructionPoint` ignores `id`. `ArraySlice` segments become `List` views.

The JVM's `log10` differs from Darwin's by one ulp on about 2.1 % of inputs, and
one characterization pin exposed this. Path and diffraction loss therefore use
`RfLog10`, a correctly rounded `log10`. It differs from Darwin on about 0.006 %
of inputs, the cases where Darwin itself isn't correctly rounded, at a cost of
about 1 µs per call. The haversine still uses JVM `sin`/`cos`/`atan2`, and no
source test pins those bit-for-bit.

## A-05: RX log service and region reprocessing

Confined state replaces the actor. The session subscription and region
reprocess task are owned by the monitor, and a superseded monitor can't
start or replace a reprocess pass. `RegionResolution` uses the already-merged
`TransportCodeRegionResolver`/`RegionScopeSemantics`; it doesn't need WP-218.

Swift iterates unordered dictionaries, so its first match is arbitrary. Here,
channel secrets are tried in ascending index order, and contact names in the
caller's map order. A JCA provider failure for one key is a non-match and is
logged, not a crash. Contact keys that fail Ed25519 point validation are dropped,
which follows WP-102.

A cancelled caller waiting on region reprocessing throws immediately; Swift's
continuation couldn't be cancelled. `updateChannels` rejects duplicate indices
with `IllegalArgumentException` where Swift would trap. Clock, locale and time
zone are injected.

## A-06: log export

`LogExportService` keeps the source's section text, ordering, number and date
formats (Gregorian calendar, ASCII digits) and size handling. It writes UTF-8 to
an injected `OutputStream`. Creating the file through Android's Storage Access
Framework and the share sheet belong to the app layer (WP-318), and app version
and device model are constructor inputs. The header names the Android system,
not "iOS". The `BatteryInfo+Display` linear percentage is reproduced inline.

## Not covered here

The two retention-prune source cases run against a test store that mirrors the
source prune/fetch algorithm. `core:services` cannot depend on the Room store in
`core:data`, so exercising them against real Room is a `core:data` follow-up.

## Receive-log restart regression readiness repair

The Android-only restart test used active subscriber count alone as readiness.
After asynchronous cancellation/start, count one can still identify the canceled
first monitor rather than the replacement. Hosted PR-165 run `38169351736` at
`99039051fdcd41fb765ea7b3b013c3299dce5724` timed out waiting for persistence after
emitting in this interval. That failure does not establish a production defect.

The fake session now counts actual eager registrations. The existing test waits
for the second registration and exactly one remaining subscriber before emitting;
its packet, five-second deadline, duplicate prevention and second-radio assertion
are unchanged. An injected test scope deterministically holds restart scheduling,
proves the old count-one condition precedes replacement registration, then checks
replacement-only persistence and complete subscription removal on stop.

Production startup, cancellation, secrets, event delivery and all pinned Swift
inputs remain unchanged. This is test synchronization evidence, not a product,
hardware or full WP-501 parity approval. Issue #168 and the bounded coordinator
reservation retain the origin and repair attribution.

The declared targeted `:core:services:test` command executed all four receive-log
consumer classes: 44 discovered/run/passed, zero failures/errors/skips. Actual
JUnit XML contains both the deterministic witness and the unchanged restart
display identity. These local results do not replace exact-candidate hosted CI.
