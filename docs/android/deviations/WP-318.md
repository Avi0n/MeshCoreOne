## Seams (contracts.md `XFeatureDependencies` pattern)

- **T-1 `BackupFeatureDependencies`**: `BackupEngine` (export / parse / atomic restore; WP-203's codec and restore, which must
  roll back on cancel or failure), `BackupDocumentPort` (system file picker, SAF), `BackupConnectionGate` (radio connected),
  `BackupImportEffects` (restored-data notifier, channel draft slots, blocked-contact cache refresh), `BackupDiagnostics`,
  `BackupStrings`. `ParsedBackup` is an opaque handle: the engine keeps its concrete envelope behind it.
- **T-2 SAF without a dependency**: `BackupDocumentPort.save/pick` return `Saved/Cancelled` and `Picked/Cancelled`; failures are
  `BackupDocumentException` (`UriUnavailable`, `PermissionRevoked`, `InsufficientSpace`, `WriteFailed`). `BackupSource` exposes the
  provider-reported size so an oversize file is rejected (`BackupContract.validateCompressedSize`, core:model) before it is read.
  The app implements the port with `ActivityResultContracts.CreateDocument/OpenDocument` and `ContentResolver`.
- **T-3 Diagnostics**: `LogExportDataSource.snapshot()` (the app gathers connection, device, battery and flushed debug logs) and
  `LogDocumentPort.saveText` (SAF). `LogExportFormatter` is pure.
- **T-4 Appearance**: `AppearanceController` is satisfied by `ThemeServiceAppearanceController(ThemeService, scope)`.
- **T-5 What's New**: `WhatsNewBaselineStore` replaces `UserDefaults`; the running `versionName` is passed to `WhatsNewState`.
- **T-6 Licenses**: `LicenseTextSource` supplies license text (bundled assets); the catalog never fabricates text.

## Adaptations and deviations

- **D-1 No purchase surface.** Appearance has no "Purchase More Themes" link (every registry theme is unlocked, selection is never
  filtered). The support screen has no tips, theme bundle/purchase cards, restore, refund, pending-approval banner, thank-you sheet
  or updater/account behavior (`RestoreState`, `ThemePreviewCard`, `ContributionsSection`, `ThemesPurchaseSection`,
  `RefundLinkSection`, `PendingPurchaseBanner`, `PurchaseThankYouSheet` are not ported; they are StoreKit-only). Support shows the
  "All themes unlocked!" card, the GitHub Sponsors link (the iOS sideload variant's external link) and the developer email.
  The support header body, contributions/restore/refund/pending strings have no localization-pipeline key and are not invented.
- **D-2 System file picker.** iOS `fileExporter`/`fileImporter` become `BackupDocumentPort`; the export confirmation
  alert, the preview sheet, the importing/cancelling/cancelled/failed/success states and the "disconnect before importing" rule are kept.
  Sheets are full-width dialogs. The iOS `userCancelled` `NSError` check becomes the `Cancelled` outcome.
  The default export file name is `MC1 Backup yyyy-MM-dd HHmmss.mc1backup` with the timestamp in UTC (the ISO-8601 format style's default zone).
- **D-3 Error text.** Typed `AppBackupError`s (core:model) use the localized strings; the document-layer
  unavailable/revoked cases reuse "The backup file is invalid or could not be read." Other failures (including low space)
  show the platform message through `exportFailed/importFailed` or the generic seam; no new copy is invented.
- **D-4 Import effects are best-effort.** A failing blocked-contact cache refresh is reported through `BackupDiagnostics` and does not turn a
  committed import into a failure (the Swift call cannot throw).
- **D-5 Log export** saves a `.txt` through the picker instead of the share sheet. The header reads `Device: <model>, Android <release>`;
  numbers use `Locale.ROOT` (Foundation used the user locale). The app, not the feature, flushes buffered logs inside `snapshot()`.
- **D-6 About**: rows are support, feedback, website, online map, GitHub, privacy policy (iOS order). The Licenses row needs a title
  with no pipeline key, so `AboutSection(licensesTitle = ...)` takes it from the app. Apple-only packages (`SwiftDocCPlugin`,
  `SymbolKit`, `MessagingUI`) are intentionally not listed; whether Emojibase, urlhaus-filter and the theme palettes ship on Android
  depends on other WPs, so the app may pass a filtered `entries` list. The 12 `Settings.bundle` locale files are WP-406's.
- **D-7 What's New**: SF Symbols become `MeshSymbol` glyphs (path details -> SIGNAL, who reacted -> MESSAGES, faster loading -> SYNC;
  stand-ins, not the original icons). The release is the pinned 1.5 entry and its upstream release-notes URL; the Android app's
  version policy decides when it presents. `WhatsNewVersion.parse` follows `Int(String)` (ASCII digits only) and drops empty components
  like Swift `split(separator:)`.
- **D-8 Node configuration integration.** The import/export screens and state live in
  `feature:settings:app:nodeconfig` behind app-supplied session, JSON codec and document ports. The App adapter captures the live
  `RadioSessionContainer` and connection token, then calls the existing WP-210 `NodeConfigService` for export, validated preview,
  ordered apply/progress, and refresh; it does not clone core planning/execution. Refresh after a committed apply is best-effort,
  matching the source workflow; refresh failure/cancellation does not undo completion, and dismissing the completion display resets
  to the file picker while an in-flight apply remains preserved. Dedicated state-holder regressions cover these boundaries.
  SAF reads and writes plain `application/json` and bypasses the compressed-backup size contract. The enclosing Advanced Settings
  host slot is supplied by WP-317; App supplies the
  slot content and owns Import/Export child routes. The ten frozen import ViewModel cases are represented by feature state/resource
  tests. The settings module suite passed in `:feature:settings:testDebugUnitTest` (296 discovered, 0 failed/errors/skipped);
  six resource-mapping, six mounted App registration/route/service, and eight provider-backed SAF cases passed in the targeted
  `:app:testDebugUnitTest` run (21 discovered, 0 failed/errors/skipped; Robolectric API 31/37 for App/SAF cases). The iOS
  `ImportKeySheet/ViewModel` is not in the ten-case assignment and is not represented as a separate Android flow.
  `Bundle+App` becomes the app-supplied `versionName`/build;
  `ExportedLogFile`/`ActivityView` are the iOS share sheet.
- **D-9 Lint**: `lintDebug` reports `LocalContextResourcesRead` warnings (same pattern as `feature:chats` D-12); no errors.
- **D-10 UI evidence boundary.** The App module already locks Compose UI test and Robolectric dependencies; WP-318 adds mounted
  Advanced-entry/route cases and provider-backed JSON SAF tests without changing dependency manifests. Robolectric results are not
  physical-device/system-picker or TalkBack evidence. Device focus/accessibility behavior remains unverified.
- **D-11 Appearance token/density**: the grid goes single-column at font scale >= 1.5 (iOS accessibility Dynamic Type sizes).

## What the app layer must wire

1. `BackupFeatureDependencies`: a `BackupEngine` over WP-203's codec/restore; a SAF `BackupDocumentPort`; the connection gate;
   `BackupImportEffects` (conversations-version bump, draft clearing, blocked-contact cache refresh); `rememberBackupStrings()`.
2. `LogExportDependencies` (snapshot over connection/device/battery/debug-log store; SAF `LogDocumentPort`; `ResourceLogExportStrings`).
3. `ThemeServiceAppearanceController(themeService, scope)` into `AppearanceScreen`.
4. `WhatsNewBaselineStore` (DataStore/SharedPreferences) and `WhatsNewState(baseline, versionName).evaluate(...)` at launch;
   present `WhatsNewSheet` when `pendingRelease` is set, `onDismiss = state::markShown`, `onSupport` to the support route.
5. Navigation for `AboutDestination` (support, feedback, licenses) and a `LicenseTextSource` over bundled license assets
   (`LICENSE`, `MeshCore/LICENSE`, `Settings.bundle/Packages/*`).
6. WP-317's settings list should host `AboutSection`, the Appearance row, and the Backup & Restore row.

## Not verifiable without a device

SAF picker behavior and grant lifetimes, provider-specific URI failures, real low-space writes, TalkBack reading order and
live-region announcements, dialog presentation, theme swatch rendering at runtime, and the Settings navigation host. Only
compilation, lint and the state-holder/presenter logic are exercised.
