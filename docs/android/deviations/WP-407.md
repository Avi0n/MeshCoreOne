# WP-407 native platform registration

Reference: `db14559b39d32322b06477c6ae676112f583db50`. The source, tests,
licenses, approved manifest and removed translation scope are unchanged.
Implementation starts from `43553e16135ffbf6a9dd3864ca501becf87a11ef`.

## Product integration

| Surface | Native implementation and boundary |
| --- | --- |
| Chats | Registers the existing list, timeline, composer, room and channel features against the process Room store and current connection-owned services. Radio-partitioned mutations, pending-message insertion events, drafts, unread state, reply identity, reactions, resend, blocking and original-text clipboard operations use existing contracts. A notification message anchor pages real history before scrolling; missing messages report a visible failure. |
| Chat content | Uses the existing bounded/SSRF-guarded HTTP, preview, malware and image services. Master and per-conversation-scope preferences govern cache access as well as automatic fetching. Manual loading, retries, native bitmap/GIF viewing, reduced-motion/pause handling and restricted cached-image sharing are wired. Image sharing grants only a deliberately exported cache file, not arbitrary private storage. |
| Settings | Registers device/radio/location/connection/advanced/notification/chat/theme/backup/language/map/support/feedback/about/license pages against existing services and preferences. Wi-Fi editing disconnects/reconnects through the single process owner. Transport comes from the live session-token-bound link, not a saved-device transport guess. Private-key replacement validates first, requires destructive confirmation, revalidates the generation, imports and refreshes device information. |
| Persistence | Process preferences and Room survive connection changes. Known-region changes await real persistence rather than treating an editor Job's completion as proof of success. Preference errors are surfaced. Backup restore retains a committed receipt after preference or post-commit cancellation failures; preference-only retry does not reimport rows or repeat slot/draft effects. |
| SAF | User-selected documents use bounded compressed reads and serialized pickers. Late results cannot answer a newer request after cancellation. Revocation, malformed providers, missing streams, write errors and ENOSPC surface typed failures. Incomplete outputs are deleted where the provider permits it; failed cleanup remains attached to the original error and is logged. |
| External actions | Resumed-host shortcut/share confirmation uses the same radio owner and durable messaging sender. Pause cancels authorization; stale hosts cannot uninstall a replacement handler. QR uses CameraX/ZXing with stride/crop/rotation-aware luma packing; denied/revoked/unavailable camera leaves manual channel-link input. External channel/hashtag navigation remains confirmation-gated. |
| Platform | Startup does not construct credential-encrypted stores before user unlock. Native splash uses the incumbent pinned icon and light/dark background; the existing adaptive/themed icon and 12-locale catalog remain. Optional BLE/camera/location hardware, denied/revoked permissions, predictive Back, resize/IME/insets and existing API-gated connection hosting are retained. Missing BLE hardware/permission is not reported as ready. Notification denial does not disable mesh messaging. |

Room events resolve persisted rows through the captured radio/session key rather
than rendering an unpartitioned event payload. Removing a default known region
first verifies that the radio's flood scope is cleared, then persists and reads
back the local region change. Restore uses the store's own IO dispatch so a
dispatcher-return cancellation cannot discard a committed receipt. Startup
failure while replaying pending actions also closes the initialized graph.
Foreground hosting follows the live link's transport even when a device retains
both Wi-Fi and Bluetooth methods; the existing Wi-Fi-only saved-method rule is
used only before a live transport exists. Presence power checks reuse the guarded
BLE capability reader, so revoked connect permission cannot trigger an
unguarded adapter access or prevent a Wi-Fi-only host from reporting its facts.

The original iOS release-specific What's New announcement is not presented as an
Android release announcement. The full categorized/searchable emoji picker is now
bound to both composer insertion and message reactions, in addition to the native
input method. It preserves the source's eight-category order, label/shortcode/tag
search, 20-entry frequent MRU and six reaction shortcuts. Reaction selection removes
the child picker before dispatching through the current radio and dismissing the
parent actions sheet. No translation provider/model or runtime dataset download is
introduced.

The frozen `project.yml` declares `emojibase-bindings` from 1.5.0. Android locks the
complete bundled iOS resource at that declared version, Git commit
`d1ed54c3bf63caa8fb48a30e16e465ac148f26f6`, rather than silently taking a newer
catalog or inventing a small replacement. `platforms/ios/Emojibase/Resources/emojibase.json`
is retained byte-for-byte (624,991 bytes, 1,932 records, SHA256
`b69315f939d4a2c4332e09b70c8278e0a9e0e7465d98c71f95e50b7ad76a4cfb`).
The bindings' Apache-2.0 notice and Emojibase Data 17.0.0's MIT notice are packaged
and discoverable in the license screen. The latter is from commit
`a5fc630a91ca42cddf3f4a66492965600fd3bce8` (the annotated release tag resolves to
this commit). Unicode License V3 was acquired from `https://www.unicode.org/license.txt`;
its exact downloaded bytes are pinned by `emoji_convert.py`, not fetched by builds.
This is notice preservation, not a claim of human legal approval.

`python tools/android-port/emoji_convert.py --source-dir <verified-input-directory>`
copies only exact checksum-bound source inputs. `--check`, also a pre-build task,
fails on a missing/changed catalog or notice and positively checks all category
counts. Frequent emojis use the existing backup-compatible UTF-8 JSON binary
preference. The synchronous feature seam enqueues complete cumulative desired lists
on a process-owned writer; it does not claim a synchronous disk commit. Saved state
is published only after DataStore's persisted result is checked. A failed selection
remains pending, surfaces an inline error/retry, and does not disable messaging.
Refreshing a picker cannot replace a newer pending/saved selection with a stale
read. Resource-local Git attributes prevent checkout newline conversion of the four
checksum-bound inputs; a real `core.autocrlf=true` temporary Git checkout regression
verifies their exact bytes. The reaction regression drives both the service and
Compose schedulers: a real delivered response, persisted recent reaction and
child/parent dismissal are asserted, not just insertion of a pending row.

Message paths now receive the current radio-partitioned device's actual key/name/id
and valid coordinate. Authorized, already requested phone fixes are preferred for
hop resolution with the radio coordinate as fallback; no GPS request occurs during
composition and a different radio's device never supplies an endpoint. App-owned
device edit notifications refresh the path/composer without creating another
connection owner. No arrival invents a path/distance. QR retry explicitly resets a
failed camera when permission is granted; old analyzers/providers/executors dispose
before remounting, and repeated/manual frames share a once-only decode guard.

Two Android-native labels ("System language" and "Open-source licenses") use English
fallback because the frozen Apple catalog has no matching platform labels. Existing
app localization is preserved; these labels do not change the frozen catalog.

Automatic backup/cloud/device transfer remains disabled. Explicit backup uses the
existing WP-203 envelope/codec/atomic restore, not a new format. App adapter tests
are not new bidirectional iOS/Android codec evidence.

## Directly necessary support

The installed reservation runtime defect is attributed to **WP-000 scope-amendment
support**, not newly owned WP-407 controller behavior. `reserve.py.runtime_sources()`
now packages top-level `inventory_rules.py`, required by `controller.model`.
Its dependencies are stdlib and the already packaged `controller.errors`.
The regression atomically installs a temporary runtime, executes its CLI using
`python -I` from outside repository import context with no repository PYTHONPATH,
loads the real current manifest and positively asserts its policy binding and
WP-407 owner. Atomic swap/hard lock, immutable runtime manifests, source pin and
terminal receipts are not bypassed. No live Git-common runtime is manually changed;
the coordinator reinstalls the merged trusted runtime after review.
The first candidate job exposed an additional verification gap: local runtime
changes were not classified as controller inputs, and the controller job did not
discover the installed-runtime suite. Directly necessary support now selects the
local runtime/top-level inventory rules and runs the existing positive-discovery
runner against `tools/android-port/local`. Classifier and workflow regressions
protect that wiring. Read-only tokens, ephemeral execution, no persisted checkout
credentials and all human/protected gates remain unchanged.

App build support uses existing catalog pins for CameraX 1.6.2 and ZXing 3.5.4.
Robolectric API33 uses the matching offline instrumented SDK alongside API31/37.
Strict dependency locks/checksums are retained. App test workers fork per test class
to release SDK sandboxes rather than accumulating native Robolectric metaspace.
These JVM sandboxes are diagnostics, not physical Android/API acceptance.
The first real instrumentation packaging exposed 50 shared navigation test method
names containing JVM-valid/Dex-invalid spaces. Only method identifiers were renamed;
the original assertion bodies are unchanged. The real IME fixture also tagged the
retained hidden root pane and the visible detail with the same identifier. It now
tags the actual setting pane only; the original keyboard-first Back behavior and
two-pixel single-inset threshold are unchanged. These are directly necessary
WP-302 test-execution support, not exemptions from navigation acceptance.
FileProvider root validation is exercised by device instrumentation: AndroidX
uses Android slash-separated paths, which cannot be validated with Windows
Robolectric filesystem paths. The production path restriction is not weakened
to make a host test pass. A long native SQLite temporary path also prevented
one existing persistence test from opening its file on Windows; the local full
run uses a separate short per-session temporary directory without changing the
test, SQLite code or acceptance threshold.

## Acceptance and remaining gates

The original registration/behavior mapping is in
[`source-mapping.md`](../evidence/WP-407/source-mapping.md). Exact-candidate hosted
job results/logs are the automated authority; no duplicate CI-result bundle is
committed, hashed or uploaded.

WP-407 is **not accepted merely because code builds or tests are discovered**.
Real API31 AOSP/no-GMS and API37 Google APIs emulators are available and platform
instrumentation now executes, including real FileProvider boundaries, offline
Room/timeline/composer/full-catalog insertion and denied camera/manual input. API37
Google APIs is not a no-GMS image. Both supplied devices execute with 4,096-byte
pages, so this is not 16-KiB native runtime evidence. Exact-candidate device commands,
positive discovery counts and permission/navigation results are reported in the PR.

The broader targeted API33/34/36 device matrix, reboot-before-first-unlock,
deliberate force-stop/background/OEM behavior and physical radio delivery are not
established by a JVM policy test or the two emulator endpoints. Their remaining
WP-502/WP-505 evidence and protected licensing/signing outcomes stay explicit;
this does not waive any WP-407 integration defect exposed by those scenarios. No physical
radio, OEM, signing, legal approval or blanket full-feature acceptance is claimed.
The source-selected full picker and its native adaptation remain reviewable;
absent translation is not an acceptance blocker. WP-501 starts only after review
and merge under the coordinator, never from this worker.
